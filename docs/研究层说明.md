# 研究层说明（A 级核实）

研究层负责网页检索和核实，**评级由代码完成**：研究结果写成 JSON，服务按第十四条 9 项逐条校验，任何一项没有「结论 + 来源链接 + 日期」就不能评 A。

## 流程

1. 服务每日扫描后写出 `data/reports/candidates-<日期>.json`（路径 A、路径 B 候选，均为 B 级待研究）。
2. 研究任务（Claude 定时任务，在用户电脑上读写 `D:\SOFT\java\PhoenixScout\data`）读取最新候选，按优先级选最多 5 个币做网页检索，
   写出 `data/research/research-<日期>-<coin_id>.json`（每个币一个文件，格式见下）。已经研究过且 7 天内的币跳过，除非价格或候选状态有大变化。
3. 服务每 10 分钟检查 `data/research/`，新文件 → 校验 9 项 → 计算第十八条、第十八条之二情景 → 评级：
   - 9 项全部通过 → A 级：当天推送（理由逐条附来源、风险、待验证项、5/10/20 倍估值情景、现在买入的三情景预期收益与时间）
   - 原来是 A 级、现在不是 → 推送降级原因
   - 其余 → B 级（或研究认定的 C 级淘汰）
4. 每天最多推 3 个 A 级。连续两周（14 天内两次以上研究且都为 A）标记“持续 A 级”。

## 研究文件格式

```json
{
  "coin_id": "coingecko id",
  "researched_at": "2026-10-17T03:00:00Z",
  "grade_hint": "A|B|C",
  "items": {
    "identity":          {"ok": true, "claim": "合约地址、链、总量已核实", "sources": [{"url": "https://…", "date": "2026-10-10"}]},
    "supply_verifiable": {"ok": true, "claim": "…", "sources": [...]},
    "economic_activity": {"ok": true, "claim": "…", "sources": [...]},
    "value_capture":     {"ok": true, "claim": "…", "mechanism": "buyback|burn|fee_burn|fee_share|real_yield_staking|other", "sources": [...]},
    "liquidity":         {"ok": true, "claim": "…", "spot_volume_30d_usd": 123456789, "sources": [...]},
    "no_security_issue": {"ok": true, "claim": "…", "sources": [...]},
    "data_consistent":   {"ok": true, "claim": "…", "sources": [...]},
    "supply_growth":     {"ok": true, "claim": "…", "supply_growth_12m_pct": 12.5, "sources": [...]},
    "audit":             {"ok": true, "claim": "…", "sources": [...]}
  },
  "scenario_inputs": {
    "price_usd": 0.42,
    "circulating_supply": 1000000000,
    "total_supply": 2000000000,
    "supply_by_month": {"12": 1100000000, "24": 1200000000, "36": 1300000000},
    "annual_revenue_usd": 25000000,
    "revenue_growth": {"conservative": 0.10, "base": 0.40, "optimistic": 0.60},
    "peer_multiples": {"p25": 8, "median": 15, "p75": 30},
    "peers": [{"name": "…", "multiple": 15, "source": "https://…"}],
    "metric": "协议年化收入（DefiLlama revenue 口径）"
  },
  "risks": ["…"],
  "unverified": ["…"],
  "catalysts": [{"claim": "…", "url": "https://…", "date": "2026-…"}],
  "summary_reason": "一句话入选理由"
}
```

规则：

- `ok` 只能是 true / false / null（未能核实）。`sources` 每条必须有 `url`（http/https）和 `date`（yyyy-MM-dd）。
- `value_capture`：回购必须是**已执行**的（不是授权或提案）；质押只承认来自手续费的真实收益（real yield），增发部分不算。
- `supply_growth`：未来 12 个月供应增长 ≤ 25% 且流通量 ≥ 总量 50% 才可 ok=true；不满足时须在 `strong_evidence` 写明需求增长能抵消稀释的强证据（附来源），否则 ok=false。
- `audit`：路径 C（早期项目）没有第三方审计不得评 A；其他路径缺审计写 ok=null 并列入 `unverified`。
- 估值倍数用“流通市值 / 年化收入”口径，`peer_multiples` 必须来自同赛道可比项目且附来源。
- 拿不到数据就写 null，绝不估造；不得给出上涨概率。

## 代码校验（9 项硬性条件，第十四条）

| 第十四条 | 研究字段 | 代码要求 |
|---|---|---|
| 1 身份、合约、供应量可核实 | identity | ok=true 且有来源 |
| 2 市值、FDV、未来 12 个月供应变化可核实 | supply_verifiable | ok=true 且有来源 |
| 3 真实经济活动 | economic_activity | ok=true 且有来源 |
| 4 可验证的价值捕获 | value_capture | ok=true、mechanism 非空、有来源 |
| 5 现货流动性足够 | liquidity | ok=true、有来源 |
| 6 无未解决的重大安全/治理问题 | no_security_issue | ok=true 且有来源 |
| 7 合理的 5 倍以上估值情景 | （代码计算） | 基准或乐观情景 36 个月内达到 5 倍，且输入齐全 |
| 8 数据来源可靠、无重大矛盾 | data_consistent | ok=true 且有来源 |
| 9 未来 12 个月供应增长 ≤ 25%，流通量 ≥ 总量 50% | supply_growth | ok=true、有来源、supply_growth_12m_pct ≤ 25 且 流通/总量 ≥ 50%（不满足须有 strong_evidence） |

路径 C 额外要求 audit ok=true。
