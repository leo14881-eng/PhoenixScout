━━━━━━━━━━━━━━━━━━━━
第一部分：目标与边界
━━━━━━━━━━━━━━━━━━━━

一、核心目标
建立一套长期运行、数据可追溯、逻辑可验证的研究系统，尽可能提前发现未来3—4年具备5—10倍潜力、极强牛市中可能达到10—20倍的山寨币。

寻找的标的特征：
长期严重超跌 + 近期真正转强（不只是高波动）+ 真实经济活动 + 可验证的价值捕获 + 合理估值 + 可控供应稀释。

二、系统边界
1. 系统只做三件事：找到符合条件的币、给出有来源的理由、推送消息给用户。
2. 不建仓、不管理持仓、不给买卖时点、不计算止盈止损、不提换仓建议；是否买、何时买由用户自行决定。
3. 禁止任何真实交易功能（下单、杠杆、合约、借贷）。允许“模拟仓”：只在本地记账、按收盘价模拟买卖，用于复盘推荐质量（第二十四条之二）。
4. 本系统未经充分历史验证，不得声称具有稳定超额收益。

第二部分：数据接口与存储
━━━━━━━━━━━━━━━━━━━━

三、数据接口
1. CoinGecko免费接口（api.coingecko.com）：价格、市值、FDV、流通量、总量、最大供应量、历史日线（仅限过去365天）。
2. DefiLlama免费接口（api.llama.fi）：协议手续费、收入。
3. 网页搜索：回购执行记录、销毁记录、解锁计划、催化事件、安全事件、审计情况，必须附来源链接和日期。
4. Binance接口因服务器所在地区限制不可用，不作为数据源。
5. CoinGecko免费接口有频率限制，每日对约100—150个候选币拉取历史数据；报告必须写明实际覆盖数量。

四、价格口径
1. 统一采用UTC日线收盘价，即UTC 00:00时间戳对应的日度价格。
2. 每个价格记录：数据源、请求时间、原始时间戳、价格口径。
3. 返回时间戳与目标日期不一致时，标记"时间戳不符"，不得当作指定日期价格使用。
4. 不得用其他日期的价格冒充指定日期价格。

五、数据存储（项目文档）
1. 原始数据：接口原始返回值。
2. 标准化数据：统一格式后的价格、市值、供应量。
3. 计算结果：区间收益、中位数、评级。
4. 每日报告与候选池状态：按日期保存，用于前后对比。

第三部分：历史基准快照

六、快照建立（最高优先级，须在2026年10月31日前完成）
原因：CoinGecko免费接口只能查询过去365天，2025年10月31日的数据将在2026年10月31日后无法获取。

步骤：
1. 获取当前市值约前1,000名的币种列表。
2. 执行排除规则（见第九条）。
3. 逐个查询每个币2025年10月31日和2026年7月31日的UTC日线收盘价和当日市值。
4. 按2025年10月31日的市值重新排名，取前500名作为"历史成分（近似）"。
5. 因频率限制，可在多次运行中分批完成，每批保存进度。

必须如实标注：
* 已退市、归零、改名的币无法从当前接口获取，历史成分存在残余幸存者偏差。
* 实际成功获取的币种数量、缺失数量、异常数量。
* 若未能完成前500名，报告实际覆盖数量，不得宣称完成前500名快照。
* 对缺失或可疑数据，可用其他可靠来源交叉核验，但必须标注来源。

七、快照保护
1. 快照文件带版本号（如snapshot_v1）和SHA-256校验值。
2. 快照建立后为只读，后续运行只能读取。
3. 读取失败或校验不符时，停止相关计算并报告，不得静默重新生成或覆盖。
4. 如需修正快照，必须生成新版本（snapshot_v2），保留旧版本，并记录修改原因。

第四部分：扫描范围与对比基准

八、扫描范围
优先研究流通市值3,000万—10亿美元的项目，不作为绝对限制。

九、排除规则（扫描前执行）
* 稳定币
* 包装币、跨链映射币
* 质押衍生币（LST/LRT）
* 交易所平台币
* 同一资产的不同交易对、不同链版本只计算一次
* 明显诈骗、严重操纵、虚假成交量、长期停止开发的项目

十、对比基准
每次计算区间收益，同时报告以下基准：

1. BTC
2. ETH
3. 中位数基准A（历史固定成分，同市值区间）：以快照中2025年10月31日排名第101—500名、且符合排除规则的山寨币为成分（按排名每隔4个取1个，共约100个，控制请求量），计算指定区间的累计收益中位数。前100名中位数另行报告，仅作市场广度参考。
   * 对退市、停止交易、数据缺失的币，不得剔除后声称是完整历史表现。
   * 必须报告：成分总数、可计算样本数、退市数、缺失数。
4. 中位数基准B（当前成分，同市值区间）：以扫描当日符合条件的第101—500名山寨币为成分（每隔4个取1个，约100个），计算滚动30天、90天收益中位数。
   * 只用于判断当前市场广度，不替代基准A。

基准A与基准B必须分别报告，不得混用。

第五部分：三条筛选路径
━━━━━━━━━━━━━━━━━━━━

十一、路径A：长期严重超跌后转强

A1. 固定区间（参考）
* 长期区间：2025-10-31至2026-07-31 UTC日线收盘价。
* 近期区间：2026-07-31至最新完整UTC日线收盘价。
* 区间收益率 = 结束日收盘价 ÷ 起始日收盘价 − 1。

长期条件（单一标准）：
* 长期区间累计跌幅 ≥ 65%，且同时跑输BTC和ETH。
* 跌幅超过90%的单独标注（归零风险高），不排除。

近期条件：
* 收益同时高于BTC、ETH和中位数基准A。
* 比三者中最好的高20个百分点以上。

A1与A2的关系：A2是必要条件；A1是参考与加分项，不满足A1不淘汰。进入研究的条件 = A2通过 + 长期弱势（快照固定区间跑输BTC和ETH；不在快照里的用365天滚动收益）+ 未出现“更低的低点”。

A2. 滚动窗口（主要判断依据、必要条件；V2.6）
* 30天、90天：收益都必须 ≥ max(BTC, ETH, 中位数基准B) + 20个百分点。
* 180天、365天：观察长期弱势是否改善。
* 固定区间与滚动窗口分别输出，不得混为一个排名。

A3. 反弹质量
* 上涨是否由真实业务改善或明确催化剂推动。
* 上涨是否集中在少数交易日。
* 现货成交量是否真实、是否持续。
* 是否存在大额解锁或集中抛售。
* 不因从低点反弹100%就认定趋势反转。
* 价格形态：近30天最低价须高于此前30—90天最低价（更高的低点），否则视为熊市反弹，不进入研究。

A4. 反弹质量硬性条件（V2.6，必须全部满足；数据不足 = 未判定 = 不入选）
* 上涨不集中：近30天最大单日涨幅 ÷ 30天总涨幅 < 50%。
* 成交量确认：近30天日均成交额 ≥ 之前90天（第31—120天）日均的1.3倍（CoinGecko total_volume）。
* 流动性下限：近30天日均成交额 ≥ 200万美元。
* 均线：收盘价站上90日均线，且90日均线不低于10天前的99%（走平或向上）。
* 入选超过30个时，按相对强度（30天超额 + 90天超额）只保留前20个。

十二、路径B：基本面领先但价格尚未反映
* 最近两个季度真实收入持续增长（优先使用DefiLlama数据）。
* 用户、交易量或网络使用量明显改善。
* 市场份额扩大。
* 价值捕获机制已实际运行。
* 未来供应增长相对可控。
* 估值相对同赛道有吸引力。
* 未来6—18个月有可验证的催化因素。
* 特别关注：业务增长较快，但币价过去90天明显跑输业务增长。

必须区分：总交易额、手续费、协议收入、净利润、实际回购、永久销毁。不得把协议收入当作普通持币人的利润。

十三、路径C：早期高成长项目
* 流通市值约3,000万—3亿美元。
* 产品已上线，或核心技术有可验证进展。
* 真实用户、付费客户或网络需求开始增长。
* 代币经济机制清晰，团队及投资人解锁可核实。
* 不依赖单一短期炒作叙事。
* 没有第三方审计的项目不得评为A级。

新币观察池：快照之后上市、或历史数据不足90天的币，单独记录，不参与路径A排名，不伪造缺失的历史数据。

第六部分：评级标准
━━━━━━━━━━━━━━━━━━━━

十四、A级硬性条件（必须全部满足）
1. 代币身份、合约和供应量可核实。
2. 流通市值、FDV和未来12个月供应变化可核实。
3. 存在真实产品使用、付费需求或其他可验证的经济活动。
4. 具有明确且可验证的价值捕获机制（见第十五条）。
5. 主要交易所现货流动性足够（近30天真实现货成交额可核实）。
6. 无尚未解决的重大安全或治理问题。
7. 存在合理的5倍以上估值情景（按第十八条计算）。
8. 核心数据来源可靠，且不存在重大矛盾。
9. 未来12个月供应增长不超过25%，且流通量占总供应量 ≥ 50%；不满足任一项者须有强证据证明需求增长足以抵消稀释。

十五、价值捕获机制（满足其一即可，必须可验证）
* 已执行的回购（不是授权或提案）
* 永久销毁
* 使用网络必须消耗代币
* 可验证的手续费分配
* 质押收益来自手续费的部分（真实收益）；由增发支付的质押收益不算
* 其他能证明业务增长会增加代币经济价值的机制

仅有治理功能、营销宣传或模糊的生态叙事，不足以证明价值捕获。

十六、运营不足12个月的项目
* 使用上市或产品上线以来的完整数据，明确记录实际运营时长。
* 不得把不足12个月的数据伪装成12个月历史。
* 不得仅凭短期高速增长认定长期趋势成立。

十七、B级与C级
B级（继续观察）：有潜力，但A级硬性条件尚未全部满足，或关键数据待验证。
C级（淘汰）：基本面严重恶化、安全风险不可接受、供应不透明、估值明显不合理或数据存在无法解释的重大矛盾。

加分项（无法核实时标注"待验证"，不阻止评级，但必须在报告中写明）：
持币地址集中度、订单簿深度与买卖价差、交易所资金流、24个月详细解锁表、同赛道估值比较。

跟踪状态：新发现 / 持续A级（连续两周及以上）/ 降级 / 淘汰。
评级不等于买入建议。每天最多输出3个A级，不强制凑数。

第七部分：估值与流动性
━━━━━━━━━━━━━━━━━━━━

十八、5—20倍估值计算方法
对每个A级候选，计算3倍、5倍、10倍、15倍、20倍情景：

1. 目标价格 = 当前价格 × 倍数。
2. 未来流通供应量 = 当前流通量 + 预计解锁 + 预计增发 − 预计销毁（按3—4年计算；无上限代币建立动态供应模型）。
3. 目标流通市值 = 目标价格 × 未来流通供应量。
4. 目标FDV = 目标价格 × 届时总供应量。
5. 所需业务规模 = 目标市值 ÷ 同赛道合理估值倍数（如市值/收入），倒推所需收入、用户或市场份额。
6. 列出同赛道可比项目的当前估值作为参照。
7. 列出实现条件和主要失败风险。

禁止：直接用当前市值乘以倍数；把历史最高价当作合理目标价；把20倍宣传为高概率结果。

十八之二、现在买入的预期收益与时间（情景推算）
对每个A级币，回答“如果按当前价格买入，大约多久能达到多少收益”，按以下方法推算：

1. 三个情景，每个情景的假设都必须写明并附数据来源：
   * 保守：业务增速取近4个季度中较低水平（或基准增速减半）；估值倍数取同赛道可比项目的下四分位。
   * 基准：业务增速取最近两个季度的年化增速；估值倍数取同赛道中位数。
   * 乐观：业务增速取基准的1.5倍；估值倍数取同赛道上四分位。
2. 推算方法：
   * 第t个月的预期市值 = 届时年化收入（或其他业务指标）× 估值倍数。
   * 第t个月的预期价格 = 预期市值 ÷ 届时流通量（按第十八条供应模型，计入解锁稀释和销毁）。
   * 预期收益倍数 = 预期价格 ÷ 当前价格。
3. 输出：
   * 6、12、24、36个月时，三个情景各自的预期收益倍数；
   * 三个情景下，达到3倍、5倍、10倍分别大约需要多久；36个月内达不到的，写“36个月内达不到”；
   * 让情景失效的最主要条件（如收入下滑、解锁超预期、估值倍数收缩）。
4. 没有收入或使用量数据可以推算时间的币，不输出时间，只输出“达到5倍需要业务达到多大规模”。
5. 模型不包含牛熊周期等整体行情因素，必须注明；实际结果可能远好于或远差于情景。
6. 结果一律标注“情景推算，不是预测或承诺”，不得给出概率。
7. 每次推送的情景推算都要记录，每季度与实际价格对比，复盘偏差并据此调整假设（与第二十六条样本外记录合并进行）。

十九、流动性审核
近30天真实现货成交额、价格上涨是否集中在少数交易日、成交量是否异常、是否存在刷量或操纵迹象。
不得把合约成交量当作现货成交量。无法验证的资金流数据不得作为确定性结论。

第八部分：数据质量与失败处理
━━━━━━━━━━━━━━━━━━━━

二十、每日数据质量记录
* API调用成功率
* 实际覆盖币种数量
* 有效历史价格覆盖率
* 供应数据覆盖率
* 基本面数据覆盖率
* 关键数据最后更新时间

二十一、异常处理
1. 不得用过期价格冒充实时价格。
2. 不得将缺失值视为零。
3. 不得用不同时间点的数据直接比较收益。
4. 不得因接口失败就判定项目不合格（标记为"数据缺失"）。
5. 不得将未完成验证的币评为A级。
6. 数据源冲突必须记录各来源数值和差异。
7. 无法完成的筛选部分，必须在报告中明确列出。
8. 快照读取失败时，停止依赖快照的计算并报告，不得重新生成覆盖。

第九部分：执行流程
━━━━━━━━━━━━━━━━━━━━

二十二、每日扫描
1. 读取并校验历史快照。
2. 拉取当前市场数据，执行排除规则。
3. 计算BTC、ETH、中位数基准A和B。
4. 运行路径A、B、C。
5. 对通过者执行统一审核和评级。
6. 输出日报，记录新增、升级、降级、淘汰。
7. 按第二十四条推送消息。
8. 不触发任何交易。

日报内容：日期与数据截止时间、数据质量记录、各基准收益、三条路径结果、最多3个A级候选（价格、市值、FDV、供应变化、价值捕获、5/10/20倍情景、跟踪状态、主要风险）、与前一日的变化。没有A级时明确写"今日无符合条件的项目"。

二十三、每周复核
1. 深度复核所有A级候选的基本面。
2. 重新核算供应、FDV和价值捕获。
3. 检查是否连续两周保持A级，标记为"持续A级"。
4. 不因此前入选就保留A级；降级或淘汰时推送原因。

二十四、推送消息
1. 出现新A级币：当天立即推送一条消息，内容：
   * 币名、代码、CoinGecko链接
   * 价格、流通市值、FDV、未来12个月供应变化（注明数据时间）
   * 入选路径（A/B/C）及关键数字（各区间收益与基准对比）
   * 入选理由：逐条对应第十四条9项硬性条件，每条附来源链接和日期
   * 价值捕获机制及证据
   * 5/10/20倍估值情景（按第十八条）
   * 现在买入的预期收益与时间：保守/基准/乐观三个情景（按第十八条之二）
   * 主要风险与仍待验证的项目
2. A级币降级或淘汰：当天推送原因。
3. 每日推送一条简短日报摘要；没有A级时写"今日无符合条件的项目"。
4. 数据质量异常（快照校验失败、覆盖率明显下降、接口持续失败）：立即推送。
5. 推送内容不得包含买卖建议或目标价承诺；第十八条之二的情景推算必须带假设，并标注“不是预测或承诺”。期望值里的概率只能来自历史回测，必须标注“统计估计”和样本数。
6. 日报格式（V2.6）：
   【A级】最多3个，没有就写“无”；【B级观察】最多5个，按期望值排序（没有期望值的按估值目标涨幅，无法估值的排在最后，同档按相对强度）；现价已高于估值目标的不列入（2026-10-18 上线验证时发现）；【今日淘汰】上一日推荐今日不在名单上的币及原因。
   每个币显示：现价｜流通市值｜FDV｜流通率；30天/90天收益及相对最强基准的超额百分点；质量分 X/5（列出缺失项）；估值目标 + 方法，或“无法估值”；期望值，或“样本不足”；防守价；主要风险（解锁、数据冲突、流动性）；理由。
   * 推荐来源（V2.6 用户决定 2026-10-18）：路径 A 回测没有证据表明有效，降级为【路径A观察】（最多显示 5 个，按相对强度），不进入 A 级/B 级观察名单，也不记模拟台账；推荐只来自路径 B（有真实收入、有估值依据）。路径 A 的任何新假设必须事先登记（见 docs/假设检验_H1.md），只有在留出的检验期有效才算“初步有效”，且不能用于真实买入。
   * 估值目标（取代“回到2025-10-31价格”，历史价格只作参考显示）：有收入的项目，目标市值 = 年化协议收入（DefiLlama 最近30天 × 365/30）× 同赛道“流通市值/年化收入”中位数（DefiLlama 同一 category、年化收入≥100万美元、倍数0.5—300、至少8个，不足用全部协议）；目标价 = 目标市值 ÷ 未来12个月流通量（研究层给出解锁计划时用“流通量×（1+12个月解锁比例）”，否则按总量，保守）。没有可核实收入、公链类或同类样本不足 → 不输出目标价，标“无法估值”，最高 B 级。
   * 期望值 = P(90天内先到估值目标) × 目标涨幅 − P(90天内先到防守价) × 防守跌幅。P 来自每周策略回测里满足同样路径 A 筛选的历史样本（同一币30天内只算一次），按收盘价先碰到哪个统计；样本不足30个、无法估值或路径 B（没有历史收入可回测）时不输出期望值。排序用期望值，不再使用盈亏比。
   * 防守价 = 现价 −35% 与近 90 天最低价中较低者。
   * 评级：A 级必须同时满足——研究层第十四条 9 项核实为 A（14天内）、质量分 ≥4、有估值目标且高于现价、没有“高稀释风险/解锁数据缺失/解锁数据冲突”。其余为 B 级观察；研究过且质量分 ≤1 的排除。
   * 回测没有证明策略有效（入选后90天平均跑赢 BTC 和山寨中位数，且样本≥30）时，日报顶部必须显示“策略尚未验证有效，仅供观察”。
   * 完整候选清单只写在日报文件里。
7. 基本面质量分（0—5分，每项1分）：团队或机构背景可核实（研究层）；产品使用或收入数据可核实（DefiLlama 有收入，或研究层）；价值捕获可验证（DefiLlama 持币人收入 holdersRevenue > 0，或研究层写明已执行的机制）；在 Binance/Coinbase/OKX/Bybit/Kraken/Upbit 至少一家有现货交易（CoinGecko 交易对）；有第三方审计（DefiLlama 审计记录，或研究层）。市值仅为自报且无第三方核实扣1分。没研究过的币标“待研究”、最高 B 级、不排除；研究过且 ≤1 分排除；2—3分最高 B 级；≥4分才有资格评 A。研究结果只用30天内的。
8. 解锁风险标签：流通率 = 流通量 ÷ 总量（CoinGecko）；未来12个月、36个月解锁占当前流通量比例，下一次大额解锁日期和数量（研究层，必须带来源；免费接口没有解锁计划数据）。流通率 <30% → 高稀释风险，最高 B；没有可核实的解锁数据 → 解锁数据缺失，最高 B；36个月解锁 >100% → 牛市窗口抛压，单独警示；写“已全部解锁”但流通率 <95% 或来源冲突 → 解锁数据冲突，不得评 A。

二十四之二、模拟台账（只记账，不下真实订单；V2.6）
目的：检验“选的币准不准”和“照着推荐投能不能稳定盈利”。
1. 两本账：
   * 选币台账：每个新推荐（A 级 + B 级观察）都记一笔，等额 1,000 美元，看选币准确度；入场时记录评级和质量分，按“质量分≥4 与其他”分组统计入场后 90 天表现。
   * 模拟组合：与真实规则一致——高倍币总预算 5,000 美元，最多 2 个，等额（受可用现金限制）。只买 A 级，或期望值 >0 的 B 级（A 优先，再按期望值）；首次建仓不限日期，之后空出的位置只在季度复核（每季度第一次扫描）时补。
2. 入场按当天 00:00 UTC 收盘价成交；同一本账同一币不重复持有。
3. 出场（只按每日收盘价，缺当天收盘价不动作；止损、止盈、逻辑失效属于风险控制，每天执行）：
   * 研究层判定逻辑失效（最新等级 C）→ 全部卖出；
   * 收盘价 ≤ 防守价 → 止损（防守价已上移到入场价时记“保本止损”）；
   * 收盘价 ≥ 估值目标 → 卖出一半，防守价上移到入场价；无法估值的持仓不做这一步；
   * 卖过一半后（无法估值的持仓：收盘价曾达到入场价 2 倍后），从最高收盘价回撤 40% → 回撤止盈；
   * 收盘价达到入场价 2 倍 → 防守价上移到入场价；
   * 持有满 1,095 天按收盘价平仓。
4. 成本：买卖各计 0.3%（手续费 0.1% + 滑点 0.2%）。
5. 记录：入场日、价格、金额、风险额、评级、质量分、期望值、估值目标、防守价、入场原因、平仓日/价/原因、盈亏金额、比例和 R 倍数；入场后 30/90/180/365 天记录该币、BTC、山寨中位数收益。每日导出 data/sim/ledger.csv。
6. 查看：状态页 http://127.0.0.1:8100/ 与实时接口 /api/sim（实时价只用于查看，不触发止盈止损）。
7. 复盘：每周日推送周复盘；已平仓不足 30 笔注明样本不足。
8. 换仓决定（真实资金）只在季度复核由用户人工决定，系统不下单。
9. 上线前回放（2026-02-14→2026-10-16，见 docs/回放_路径A_V2.6.md）：V2.6 平均每天入选 5.9 个（V2.5 为 53.8 个）；但入选后 90 天平均 −27.0%，相对山寨中位数 −5.0 个百分点，低于随机选币（−10.4%）；选币台账 +8,261 美元完全来自最好的两笔，去掉后 −16,230 美元。结论：路径 A 价格信号本身尚未验证有效，结论以上线后的真实记录为准。

第十部分：策略有效性验证

二十五、验证任务
每周策略回测（V2.6）：每周日用本地全部日线，对过去每一天模拟运行一次路径 A 筛选（只用当天及以前的数据），记录每个入选币之后 30/90/180 天收益，对比 BTC、ETH、山寨中位数，统计胜率、平均超额、平均最大回撤、归零或数据中断比例；结果写进日报“策略回测”一节，并作为期望值的概率来源。“质量分≥4 与其他”两组对比没有历史质量分可用，从上线起在选币台账里累计。
同时从系统运行之日起，每天记录候选及其后续表现（样本外数据），每季度检查：
1. 历史上满足"严重超跌 + 近期转强"的币，之后90天、180天、365天的表现。
2. 相对BTC、ETH和中位数基准是否有超额收益。
3. 入选后的最大回撤。
4. 有多少候选后来退市、归零或持续下跌。
5. 30天、90天相对强弱是否有预测价值。
6. 加入基本面和供应筛选后结果是否改善。
7. 不同市值区间的表现差异。
8. 结果是否高度依赖某一段行情。

验证纪律：避免幸存者偏差、不使用未来数据、不只统计成功案例、计入交易成本和流动性、不用事后挑选的最佳参数冒充真实表现。

二十六、验证局限（必须如实说明）
* 免费数据只有365天，覆盖不了一个完整牛熊周期，只能进行一年内的初步验证。
* 无法证明策略能跨周期稳定获得超额收益。
* 自系统运行起，每日记录候选及其后续表现，逐步积累真实的样本外数据，每季度更新一次验证结果。

第十一部分：数据真实性纪律
━━━━━━━━━━━━━━━━━━━━

1. 每天联网查询，所有价格注明时间。
2. 统一使用UTC日线收盘价和完整区间累计收益。
3. 所有基准使用相同日期和口径。
4. 不得用历史最高价代替区间起点。
5. 不得混用流通市值与FDV。
6. 不得忽略未来解锁。
7. 不得把缺失数据填零。
8. 不得使用未经核实的收入数字。
9. 不得把回购授权当作实际回购。
10. 不得伪造上涨概率。
11. 不得声称扫描全市场而没有覆盖证据。
12. 不得用当前市值排名替代历史市值排名。
13. 数据不足时必须说明，不得强行推荐。

最终原则：宁可没有推荐，也不推荐缺乏证据的币；宁可错过短期暴涨，也不为了追求20倍而承担无法评估的永久损失风险。
