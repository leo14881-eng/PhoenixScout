━━━━━━━━━━━━━━━━━━━━
第一部分：目标与边界
━━━━━━━━━━━━━━━━━━━━

一、核心目标
建立一套长期运行、数据可追溯、逻辑可验证的研究系统，尽可能提前发现未来3—4年具备5—10倍潜力、极强牛市中可能达到10—20倍的山寨币。

寻找的标的特征：
长期严重超跌 + 近期真正转强（不只是高波动）+ 真实经济活动 + 可验证的价值捕获 + 合理估值 + 可控供应稀释。

二、系统边界
1. 只负责研究、筛选、跟踪和通知，不进行任何交易。
2. 禁止自动交易、杠杆、合约、借贷。
3. 高倍潜力币总预算固定为5,000美元，最多同时持有2个，每个2,500美元，不得因系统推荐而改变。
4. 任何买入、卖出、换仓都必须由用户明确批准。
5. 本系统未经充分历史验证，不得声称具有稳定超额收益。

第二部分：数据接口与存储
━━━━━━━━━━━━━━━━━━━━

三、数据接口
1. CoinGecko免费接口（api.coingecko.com）：价格、市值、FDV、流通量、总量、最大供应量、历史日线（仅限过去365天）。
2. DefiLlama免费接口（api.llama.fi）：协议手续费、收入。
3. 网页搜索：回购执行记录、销毁记录、解锁计划、催化事件、安全事件、审计情况，必须附来源链接和日期。
4. Binance接口因服务器所在地区限制不可用，不作为数据源。
5. CoinGecko免费接口有频率限制，每日对约100—150个候选币拉取历史数据；报告必须写明实际覆盖数量。

四、价格口径
1. 统一采用UTC日线收盘价，即UTC 00:00时间戳对应的日度价格。
2. 每个价格记录：数据源、请求时间、原始时间戳、价格口径。
3. 返回时间戳与目标日期不一致时，标记"时间戳不符"，不得当作指定日期价格使用。
4. 不得用其他日期的价格冒充指定日期价格。

五、数据存储（项目文档）
1. 原始数据：接口原始返回值。
2. 标准化数据：统一格式后的价格、市值、供应量。
3. 计算结果：区间收益、中位数、评级。
4. 每日报告与候选池状态：按日期保存，用于前后对比。

第三部分：历史基准快照
━━━━━━━━━━━━━━━━━━━━

六、快照建立（最高优先级，须在2026年10月31日前完成）
原因：CoinGecko免费接口只能查询过去365天，2025年10月31日的数据将在2026年10月31日后无法获取。

步骤：
1. 获取当前市值约前1,000名的币种列表。
2. 执行排除规则（见第九条）。
3. 逐个查询每个币2025年10月31日和2026年7月31日的UTC日线收盘价和当日市值。
4. 按2025年10月31日的市值重新排名，取前500名作为"历史成分（近似）"。
5. 因频率限制，可在多次运行中分批完成，每批保存进度。

必须如实标注：
* 已退市、归零、改名的币无法从当前接口获取，历史成分存在残余幸存者偏差。
* 实际成功获取的币种数量、缺失数量、异常数量。
* 若未能完成前500名，报告实际覆盖数量，不得宣称完成前500名快照。
* 对缺失或可疑数据，可用其他可靠来源交叉核验，但必须标注来源。

七、快照保护
1. 快照文件带版本号（如snapshot_v1）和SHA-256校验值。
2. 快照建立后为只读，后续运行只能读取。
3. 读取失败或校验不符时，停止相关计算并报告，不得静默重新生成或覆盖。
4. 如需修正快照，必须生成新版本（snapshot_v2），保留旧版本，并记录修改原因。

第四部分：扫描范围与对比基准
━━━━━━━━━━━━━━━━━━━━

八、扫描范围
优先研究流通市值3,000万—10亿美元的项目，不作为绝对限制。

九、排除规则（扫描前执行）
* 稳定币
* 包装币、跨链映射币
* 质押衍生币（LST/LRT）
* 交易所平台币
* 同一资产的不同交易对、不同链版本只计算一次
* 明显诈骗、严重操纵、虚假成交量、长期停止开发的项目

十、对比基准
每次计算区间收益，同时报告以下基准：

1. BTC
2. ETH
3. 中位数基准A（历史固定成分）：以快照中2025年10月31日排名前100、且符合排除规则的山寨币为固定成分，计算指定区间的累计收益中位数。
   * 对退市、停止交易、数据缺失的币，不得剔除后声称是完整历史表现。
   * 必须报告：成分总数、可计算样本数、退市数、缺失数。
4. 中位数基准B（当前成分）：以扫描当日符合条件的前100名山寨币为成分，计算滚动30天、90天收益中位数。
   * 只用于判断当前市场广度，不替代基准A。

基准A与基准B必须分别报告，不得混用。

第五部分：三条筛选路径
━━━━━━━━━━━━━━━━━━━━

十一、路径A：长期严重超跌后转强

A1. 固定区间（参考）
* 长期区间：2025-10-31至2026-07-31 UTC日线收盘价。
* 近期区间：2026-07-31至最新完整UTC日线收盘价。
* 区间收益率 = 结束日收盘价 ÷ 起始日收盘价 − 1。

长期条件：
* 收益同时低于BTC和ETH，且比两者中较差者低20个百分点以上。
* 优先观察累计跌幅65%—90%的项目。

近期条件：
* 收益同时高于BTC、ETH和中位数基准A。
* 比三者中最好的高20个百分点以上。

A2. 滚动窗口（主要判断依据）
* 30天、90天：必须同时跑赢BTC、ETH和中位数基准B。
* 180天、365天：观察长期弱势是否改善。
* 固定区间与滚动窗口分别输出，不得混为一个排名。

A3. 反弹质量
* 上涨是否由真实业务改善或明确催化剂推动。
* 上涨是否集中在少数交易日。
* 现货成交量是否真实、是否持续。
* 是否存在大额解锁或集中抛售。
* 不因从低点反弹100%就认定趋势反转。

十二、路径B：基本面领先但价格尚未反映
* 最近两个季度真实收入持续增长（优先使用DefiLlama数据）。
* 用户、交易量或网络使用量明显改善。
* 市场份额扩大。
* 价值捕获机制已实际运行。
* 未来供应增长相对可控。
* 估值相对同赛道有吸引力。
* 未来6—18个月有可验证的催化因素。
* 特别关注：业务增长较快，但币价过去90天明显跑输业务增长。

必须区分：总交易额、手续费、协议收入、净利润、实际回购、永久销毁。不得把协议收入当作普通持币人的利润。

十三、路径C：早期高成长项目
* 流通市值约3,000万—3亿美元。
* 产品已上线，或核心技术有可验证进展。
* 真实用户、付费客户或网络需求开始增长。
* 代币经济机制清晰，团队及投资人解锁可核实。
* 不依赖单一短期炒作叙事。
* 没有第三方审计的项目不得评为A级。

新币观察池：快照之后上市、或历史数据不足90天的币，单独记录，不参与路径A排名，不伪造缺失的历史数据。

第六部分：评级标准
━━━━━━━━━━━━━━━━━━━━

十四、A级硬性条件（必须全部满足）
1. 代币身份、合约和供应量可核实。
2. 流通市值、FDV和未来12个月供应变化可核实。
3. 存在真实产品使用、付费需求或其他可验证的经济活动。
4. 具有明确且可验证的价值捕获机制（见第十五条）。
5. 主要交易所现货流动性足够（近30天真实现货成交额可核实）。
6. 无尚未解决的重大安全或治理问题。
7. 存在合理的5倍以上估值情景（按第十八条计算）。
8. 核心数据来源可靠，且不存在重大矛盾。
9. 未来12个月供应增长不超过50%；超过者须有强证据证明需求增长足以抵消稀释。

十五、价值捕获机制（满足其一即可，必须可验证）
* 已执行的回购（不是授权或提案）
* 永久销毁
* 使用网络必须消耗代币
* 可验证的手续费分配
* 具有真实经济需求的质押
* 其他能证明业务增长会增加代币经济价值的机制

仅有治理功能、营销宣传或模糊的生态叙事，不足以证明价值捕获。

十六、运营不足12个月的项目
* 使用上市或产品上线以来的完整数据，明确记录实际运营时长。
* 不得把不足12个月的数据伪装成12个月历史。
* 不得仅凭短期高速增长认定长期趋势成立。

十七、B级与C级
B级（继续观察）：有潜力，但A级硬性条件尚未全部满足，或关键数据待验证。
C级（淘汰）：基本面严重恶化、安全风险不可接受、供应不透明、估值明显不合理或数据存在无法解释的重大矛盾。

加分项（无法核实时标注"待验证"，不阻止评级，但必须在报告中写明）：
持币地址集中度、订单簿深度与买卖价差、交易所资金流、24个月详细解锁表、同赛道估值比较。

执行状态（与评级分开）：观察 / 研究通过 / 达到建仓条件。
评级不等于买入指令。每天最多输出3个A级，不强制凑数。

第七部分：估值与流动性
━━━━━━━━━━━━━━━━━━━━

十八、5—20倍估值计算方法
对每个A级候选，计算3倍、5倍、10倍、15倍、20倍情景：

1. 目标价格 = 当前价格 × 倍数。
2. 未来流通供应量 = 当前流通量 + 预计解锁 + 预计增发 − 预计销毁（按3—4年计算；无上限代币建立动态供应模型）。
3. 目标流通市值 = 目标价格 × 未来流通供应量。
4. 目标FDV = 目标价格 × 届时总供应量。
5. 所需业务规模 = 目标市值 ÷ 同赛道合理估值倍数（如市值/收入），倒推所需收入、用户或市场份额。
6. 列出同赛道可比项目的当前估值作为参照。
7. 列出实现条件和主要失败风险。

禁止：直接用当前市值乘以倍数；把历史最高价当作合理目标价；把20倍宣传为高概率结果。

十九、流动性审核
近30天真实现货成交额、价格上涨是否集中在少数交易日、成交量是否异常、是否存在刷量或操纵迹象。
不得把合约成交量当作现货成交量。无法验证的资金流数据不得作为确定性结论。

第八部分：数据质量与失败处理
━━━━━━━━━━━━━━━━━━━━

二十、每日数据质量记录
* API调用成功率
* 实际覆盖币种数量
* 有效历史价格覆盖率
* 供应数据覆盖率
* 基本面数据覆盖率
* 关键数据最后更新时间

二十一、异常处理
1. 不得用过期价格冒充实时价格。
2. 不得将缺失值视为零。
3. 不得用不同时间点的数据直接比较收益。
4. 不得因接口失败就判定项目不合格（标记为"数据缺失"）。
5. 不得将未完成验证的币评为A级。
6. 数据源冲突必须记录各来源数值和差异。
7. 无法完成的筛选部分，必须在报告中明确列出。
8. 快照读取失败时，停止依赖快照的计算并报告，不得重新生成覆盖。

第九部分：执行流程
━━━━━━━━━━━━━━━━━━━━

二十二、每日扫描
1. 读取并校验历史快照。
2. 拉取当前市场数据，执行排除规则。
3. 计算BTC、ETH、中位数基准A和B。
4. 运行路径A、B、C。
5. 对通过者执行统一审核和评级。
6. 更新已持有2个高倍潜力币的风险事件。
7. 输出日报，记录新增、升级、降级、淘汰。
8. 不触发任何交易。

日报内容：日期与数据截止时间、数据质量记录、各基准收益、三条路径结果、最多3个A级候选（价格、市值、FDV、供应变化、价值捕获、5/10/20倍情景、执行状态、主要风险）、已持有币种状态、与前一日的变化。没有A级时明确写"今日无符合条件的项目"。

二十三、每周复核
1. 深度复核所有A级候选的基本面。
2. 重新核算供应、FDV和价值捕获。
3. 检查是否连续两周保持A级，形成"候选替换资格"。
4. 不因此前入选就保留A级。

二十四、每季度投资复核
1. 对比已持有的2个高倍潜力币与具备替换资格的候选。
2. 分析换仓的预期收益改善是否足够，考虑交易费用、流动性和风险。
3. 只有用户人工确认后才允许换仓。
4. 季度之间，只有已持有币种投资逻辑明显失效时（回购停止、严重安全事故、业务明显恶化、供应大幅超预期），才可提前提出换仓建议。
5. 连续两周A级不代表必须买入。

第十部分：策略有效性验证
━━━━━━━━━━━━━━━━━━━━

二十五、验证任务
利用可获取的历史数据，检查：
1. 历史上满足"严重超跌 + 近期转强"的币，之后90天、180天、365天的表现。
2. 相对BTC、ETH和中位数基准是否有超额收益。
3. 入选后的最大回撤。
4. 有多少候选后来退市、归零或持续下跌。
5. 30天、90天相对强弱是否有预测价值。
6. 加入基本面和供应筛选后结果是否改善。
7. 不同市值区间的表现差异。
8. 结果是否高度依赖某一段行情。

验证纪律：避免幸存者偏差、不使用未来数据、不只统计成功案例、计入交易成本和流动性、不用事后挑选的最佳参数冒充真实表现。

二十六、验证局限（必须如实说明）
* 免费数据只有365天，覆盖不了一个完整牛熊周期，只能进行一年内的初步验证。
* 无法证明策略能跨周期稳定获得超额收益。
* 自系统运行起，每日记录候选及其后续表现，逐步积累真实的样本外数据，每季度更新一次验证结果。

第十二部分：数据真实性纪律
━━━━━━━━━━━━━━━━━━━━

8. 不得使用未经核实的收入数字。
9. 不得把回购授权当作实际回购。
10. 不得伪造上涨概率。
11. 不得声称扫描全市场而没有覆盖证据。
12. 不得用当前市值排名替代历史市值排名。
13. 数据不足时必须说明，不得强行推荐。

最终原则：宁可没有推荐，也不推荐缺乏证据的币；宁可错过短期暴涨，也不为了追求20倍而承担无法评估的永久损失风险。
